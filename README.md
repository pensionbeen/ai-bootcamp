# 서울시 조례 Q&A — 근거를 코드가 확인하는 조례 답변 API

서울특별시 조례 6종(2026-10-01 시행 판본)에서 근거 조문을 찾아 쉬운 말로 답하고, 인용 조문은 모델이 아니라 코드가 원문 행에서 만들어 붙이며, 근거를 확인하지 못하면 `"확인 불가"`와 빈 인용으로 답합니다.

대상 조례: 주차장 설치 및 관리 조례, 동물보호 조례, 자전거이용 활성화에 관한 조례, 도시공원 조례, 청년 기본 조례, 금연환경 조성 및 간접흡연 피해방지조례(모두 서울특별시 본청). 자치구 조례·규칙은 대상이 아닙니다.

## 구조 한 장

```
질문
 │
 ▼
질문 임베딩 (solar-embedding-2-query)
 │
 ▼
로컬 SQLite 검색: 조문·부칙·별표 벡터에서 상위 8개(top_k 8)
 + 확장: 검색된 조문이 명시적으로 가리키는 다른 조·별표를 원문 참조 관계로 추가
 │
 ▼
초안 생성
  검색된 요금표·감면 조항 등의 원문과 적용 조건을 코드로 확인할 수 있으면 그 근거로 초안을 조립한다.
  그 밖의 질문은 solar-pro4가 답 문장과 근거 번호를 엄격한 JSON 스키마로 생성한다.
 │
 ▼
답 자동 검증: 모델이 고른 근거가 실제로 찾은 조문인지, 답에 나온 숫자·금액이 원문과 같은지 프로그램이 확인합니다
 │
 ▼
조문 확인 (solar-pro4 1회): 인용한 조문이 질문이 묻는 사항을 실제로 다루는지만 묻는다
 │
 ▼
공개 응답 {answer, citation, source_url, effective_date}
  citation 문자열은 코드가 원문 행의 조·항·별표 라벨로 만든다
```

검사에서 막히거나 조문 확인이 "해당 규정 없음"으로 답하면 답 초안을 공개하지 않고 `{"answer": "확인 불가", "citation": [], "source_url": "", "effective_date": ""}`로 응답합니다. 조문 확인 호출이 시간 안에 끝나지 않으면 답 자동 검증을 이미 통과한 초안을 그대로 공개합니다(시간 초과로 정상 답을 버리지 않기 위한 선택).

## 실행 방법

아래 명령은 Windows PowerShell 기준입니다. Linux·macOS에서는 `.venv/Scripts/python.exe` 대신 `.venv/bin/python`을 씁니다. Python 3.15에서 확인했습니다.

### 1. 준비

저장소를 받은 폴더에서 차례로 실행합니다.

1. 가상환경을 만들고 필요한 패키지(`requests`, `python-dotenv`)를 설치합니다. 서버는 Python 표준 라이브러리로 돌아가서 웹 프레임워크가 필요 없습니다.

   ```powershell
   python -m venv .venv
   .venv/Scripts/python.exe -m pip install -r requirements.txt
   # Linux·macOS: .venv/bin/python -m pip install -r requirements.txt
   ```

2. `.env.example`을 `.env`로 복사하고 `UPSTAGE_API_KEY=` 뒤에 Upstage 콘솔에서 발급한 API 키를 넣습니다. `.env`는 Git에 올라가지 않고, 키는 응답에도 나오지 않습니다. 같은 이름의 환경 변수가 있으면 그것을 먼저 씁니다.

   ```powershell
   Copy-Item .env.example .env
   # Linux·macOS: cp .env.example .env
   ```

3. 검색 DB(`data/processed/rag/2026-10-01/71ce40874477c9a4bc9d/rag.sqlite3`, 약 30MB)는 저장소에 들어 있습니다. 조문·부칙·별표 검색 조각 810개가 있고, 미리 저장한 질문·답변은 0개입니다. 서버는 DB를 읽기 전용으로 열고 목록 파일과 대조합니다.

### 2. 서버 기동

```powershell
# 같은 PC에서만 접속
.venv/Scripts/python.exe -B run.py serve --port 8000
# 다른 컴퓨터가 접속해야 할 때
.venv/Scripts/python.exe -B run.py serve --host 0.0.0.0 --port 8000
```

동시에 처리할 질문 수와 대기 수는 `--workers 4 --queue-size 12`처럼 바꿀 수 있습니다(기본값이 4와 12입니다).

기동 뒤 브라우저나 `curl`로 `http://127.0.0.1:8000/health`를 열어 확인합니다. 이 주소는 키·DB·필요한 파일이 준비됐는지만 보고 모델을 호출하지 않습니다. 키가 없거나 DB가 맞지 않으면 503을 돌려줍니다.

### 3. 질문 보내기 (대회 키트 형식)

```bash
curl -sS -m 90 -X POST http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data '{"question":"서울시 청년 기본 조례에서 말하는 청년은 몇 살부터 몇 살까지인가요?"}'
```

PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
$payload = @{ question = '서울시 금연구역에서 담배를 피우면 과태료가 얼마인가요?' } | ConvertTo-Json
$r = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/ask -TimeoutSec 90 -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($payload))
$r.answer; $r.citation; $r.source_url; $r.effective_date
```

응답 필드:

| 필드 | 뜻 |
|---|---|
| `answer` | 답 문장(문자열). 근거가 없으면 `"확인 불가"` |
| `citation` | 인용 조문 라벨 배열. 예: `서울특별시 ○○ 조례 제7조 제1항`, `… 별표 1`. 확인 불가면 `[]` |
| `source_url` | 첫 인용 조례의 법제처 링크(시행 판본 고정). 확인 불가면 빈 문자열 `""` |
| `effective_date` | 첫 인용 조례의 시행일(`YYYY-MM-DD`). 확인 불가면 빈 문자열 `""` |

응답 본문에는 대회 키트와 똑같이 이 네 가지만 들어갑니다. 서버가 질문을 어떻게 처리했는지(정상 처리, 시간 초과, 처리 오류 등)는 본문이 아니라 응답 헤더 `X-Rag-Status`에 적어 두므로, 운영자는 이 헤더로 확인할 수 있습니다.

#### 생활 민원에서 근거를 확인할 수 없을 때

서울시 조례 6종에서 질문의 근거를 확인할 수 없거나 조례 범위를 벗어나면, 시민용 `/ui/ask`와 `GET /jobs/<번호>`가 국민신문고 주소를 `result.inquiry_url`에 담습니다. 화면에서 문의 링크를 연결할 때 이 필드를 읽으면 됩니다. 예를 들어 근거 부족으로 완료된 시민용 응답에는 다음 항목이 들어갑니다.

```json
{
  "status": "completed",
  "result": {
    "status": "insufficient_evidence",
    "response": {"answer": "확인 불가", "citation": []},
    "inquiry_url": "https://www.epeople.go.kr/"
  }
}
```

대회용 동기 `POST /ask`는 동일한 문의 주소를 HTTP 헤더 `Link: <https://www.epeople.go.kr/>; rel="help"`로 제공합니다. 네 필드의 JSON 본문에서는 인용·출처·시행일이 비어 있습니다. 처리 오류와 시간 초과에는 문의 주소를 보내지 않습니다. 조례가 다른 법령을 명시적으로 준용하면 해당 조례를 인용하고 외부 확인이 필요한 사항을 설명합니다.

시민 화면은 응답에 `result.inquiry_url`이 있을 때 그 값을 국민신문고 문의 버튼의 링크로 씁니다.

### 4. 대회 키트로 점검하기

브라우저에서 `/test`를 열고 **요청 보내고 검사**를 누르면 브라우저와 저장소의 Python 제출 검사기가 각각 같은 질문을 공개 `/ask`에 보냅니다. 두 요청의 HTTP 상태, 응답 시간, JSON 원문과 네 필드의 형식을 비교할 수 있습니다. 답변의 정확도와 공식 대회 점수는 별도 평가 대상입니다.

Python 요청을 활성화하려면 서버를 시작할 때 `SUBMISSION_CHECK_BASE_URL`에 경로를 제외한 공개 주소를 지정하세요. 예를 들어 이 배포의 값은 `https://upstage.makertion.com`입니다. Python 요청도 공개 도메인을 거치므로 프록시의 접근 제한이 있으면 해당 오류 본문이 그대로 표시됩니다.

서버를 띄운 상태에서 대회 스타터 키트 폴더로 옮겨 아래 명령을 실행합니다.

```powershell
python -X utf8 check.py --url http://127.0.0.1:8000/ask
```

### 5. 외부에서 접속하게 하기

- 다른 컴퓨터가 접속하려면 서버를 `--host 0.0.0.0`으로 띄웁니다.
- 서버 자체는 http로만 응답합니다. https 주소가 필요하면 터널 서비스나 리버스 프록시를 서버 앞에 둡니다.
- 질문 API는 인증 없이 호출할 수 있으므로 외부 접속은 꼭 필요한 기간에만 엽니다.

#### 요청 기록 확인

`/admin/requests`에서 `POST /ask` 요청의 질문, 접수 시각, HTTP 상태, 처리 시간, 응답 JSON을 확인할 수 있습니다. 서버 환경 변수 `REQUEST_LOG_PASSWORD`를 설정하고 아이디 `admin`으로 로그인합니다. 운영에서는 HTTPS 주소로 접속합니다.

요청 기록은 기존 실행 데이터 영역의 SQLite 파일에 저장하며 최신 10,000건을 보관합니다. 같은 질문을 반복해서 보내도 요청별로 표시합니다. 이전에 저장된 질문·답변도 가져와 표시하며, 당시 접수 시각과 발신자 정보는 알 수 없어 기존 저장 자료로 표시합니다.

IP·User-Agent·Cloudflare 요청 번호는 발신자 확인에 참고할 수 있습니다. 주최 측의 점검 시각이나 알려준 발신 정보와 대조하면 해당 요청을 찾기 쉽습니다. 기록되는 요청 내용은 질문과 대기시간 필드이며 인증 헤더와 쿠키는 수집하지 않습니다.

### 6. 시간 제한 대비 (90초)

대회 채점기는 90초를 기다립니다. 서버는 요청을 받은 시점부터 최대 80초까지 답을 기다렸다가, 그 안에 끝나지 않으면 `{"answer":"확인 불가","citation":[],"source_url":"","effective_date":""}`를 먼저 돌려줍니다. 남은 10초는 연결·전송 여유입니다. 처리 오류나 대기열이 가득 찬 경우도 같은 모양으로 HTTP 200 응답을 보냅니다(채점기는 오류 응답의 본문을 읽지 못하기 때문). 이런 응답은 "근거가 없다"는 뜻이 아니며, 헤더 `X-Rag-Status`에 `deadline_exceeded`(시간 초과), `processing_error`·`failed`·`interrupted`(처리 오류), `queue_full`(대기열 가득 참)로 구분해 적습니다. 시간 초과여도 작업은 계속 돌아가며, 헤더 `X-Rag-Job-Id`의 작업 번호로 `GET /jobs/<작업 번호>`를 부르면 끝난 뒤 결과를 받을 수 있습니다.

기본으로 서로 다른 질문 4개를 동시에 처리하고, 12개까지 대기시킵니다. 동시 처리는 1~16, 대기는 0~64 사이로 바꿀 수 있고, 환경 변수 `LOCAL_RAG_WORKERS`, `LOCAL_RAG_QUEUE_SIZE`로도 지정할 수 있습니다. 처리 중 같은 질문을 제출하면 진행 중인 작업 번호를 받습니다. 완료 후 다시 제출하면 새 작업 번호로 검색·초안 생성·조문 검사를 수행합니다. 기존 질문 임베딩은 공유할 수 있으며, 초안과 조문 검사 모델 응답은 해당 작업 안에서만 재사용합니다. 기존 작업 번호를 조회하면 당시 결과가 반환됩니다. 관리자 요청 기록은 별도로 보관합니다.

서버를 실행하는 동안에는 `run.py ask`처럼 명령줄에서 질문을 보내는 실행을 함께 돌리지 않습니다. 두 쪽이 같은 요청 기록을 쓰기 때문입니다.

### 7. 테스트

```powershell
.venv/Scripts/python.exe -B run.py test
```

일부 시험은 저장소에 넣지 않은 원본 자료가 있어야 하므로, 그 자료가 없으면 자동으로 건너뜁니다.

| 위치 | 내용 |

| `tests/` | 자동 테스트 |

## 화면 사용법

- 서버를 띄운 뒤(`run.py serve`, 기본 포트 8000) 브라우저에서 `http://127.0.0.1:8000/`을 엽니다. 별도 설치나 외부 자원 없이 같은 서버가 화면과 API를 함께 제공합니다. 첫 화면은 시민용 Lawddy 화면(`src/web/index.html`, 스크립트·스타일·이미지는 `src/web/app/`)이고, 이전 기본 화면은 `/legacy.html`에 남겨 두었습니다.
- 화면은 질문을 `POST /ui/ask`로 보내는데, 채점용 `POST /ask`와 같은 방식으로 답을 만들고 응답에 처리 상태와 인용별 링크·시행일을 더 담아 돌려줍니다.
- 첫 화면의 검색창에 질문하거나 "분야별 자주 묻는 질문"의 예시를 누릅니다. 결과 화면 아래 입력창에서 이어서 질문할 수 있습니다(Enter 보내기, Shift+Enter 줄바꿈). 답은 보통 수십 초 걸리며, 80초를 넘기면 화면이 3초마다 결과를 자동으로 다시 확인합니다(최대 10분).
- "처음 화면으로"(또는 브라우저 뒤로가기)를 누르면 대화를 지우고, 기다리던 질문도 화면에서 취소해 바로 새 질문을 보낼 수 있습니다. 서버에서 이미 시작된 작업은 끝까지 처리됩니다.
- 답 아래 "근거 조항"의 "원문 보기"를 누르면 법제처 국가법령정보센터의 해당 조례 원문이 새 탭에서 열리고, 옆에 시행일이 표시됩니다.
- 조례에 근거가 없는 질문은 "확인 불가"와 그 사유를 보여 주고, 서버가 `result.inquiry_url`을 주면 국민신문고 문의 버튼을 함께 보여 줍니다. 처리 오류나 대기열 초과는 "확인 불가"와 구분해 다시 시도 안내로 표시합니다.
- 화면의 질문도 채점용 `/ask`와 같은 대기열(기본 동시 4건 처리, 12건 대기)을 씁니다. 완료된 질문을 다시 제출하면 모델 호출 비용이 다시 발생할 수 있습니다. 안내 범위는 2026-10-01 기준 서울특별시 조례 6종입니다.
- 답(근거 확인·확인 불가) 아래 **민원 초안 쓰기**를 누르면 겪은 상황(선택)을 받아 `POST /ui/draft`로 민원 글 초안을 만듭니다. 모델(solar-pro4)은 제목·민원 요지·요청 사항만 쓰고, 관련 조례 목록과 원문 링크는 서버 코드가 그 답의 근거에서 붙입니다. 모델 글에 근거 목록에 없는 조문 번호, 질문·상황·답에 없는 숫자, 주소가 있거나 모델을 부를 수 없으면 기본 양식으로 채우고 알립니다. 초안은 고쳐 쓰고 복사해 서울시 응답소(https://eungdapso.seoul.go.kr/)나 국민신문고(https://www.epeople.go.kr/)에 직접 신청합니다. 개인정보는 받지 않으며, 동시에 2건까지 만듭니다(넘으면 429).
- **사진으로 묻기**: 검색창의 카메라 버튼으로 표지판·고지서·안내문 사진을 올리면, 화면이 사진을 1600px JPEG로 줄여(위치 정보 제거) `POST /ui/photo`로 보냅니다. 서버는 Upstage OCR(`document-digitization`, model `ocr`)로 글자를 읽고 차량번호·전화번호·주민등록번호·이메일을 [가림]으로 바꾼 뒤, solar-pro4로 질문 하나를 제안합니다. 사진은 저장하지 않고, 제안 질문은 시민이 확인해 직접 보냅니다. 동시에 2건까지(429).
- **말로 묻기**: 마이크 버튼은 브라우저 음성 인식(Web Speech API, ko-KR)을 지원하는 브라우저에서만 보입니다. 인식한 문장은 입력칸에만 채우고 자동으로 보내지 않습니다. 음성 처리는 브라우저 제공자(예: Chrome은 Google)의 서비스로 처리됩니다.
- **조문 원문 펼쳐 보기**: 근거 조항 아래 버튼을 누르면 `POST /ui/sources`가 그 답에 인용된 조항의 원문을 검색 DB(읽기 전용)에서 꺼내 보여 주고, 답에 나온 숫자·금액(단위가 같은 것, 세 자리 이상 숫자)을 형광펜으로 표시합니다. 조문 번호는 표시하지 않습니다.
- 화면 스크립트 시험: `node --test tests/test_web_app_api.mjs tests/test_ask_validation.mjs` (node가 있으면 `run.py test`에서도 함께 돌아갑니다).

화면을 고치려면 [화면 연결 안내](docs/ui-guide.md)를 봅니다.

## 카카오톡 채널

같은 서버가 카카오 i 오픈빌더 스킬 요청도 `POST /kakao/skill`로 받습니다. 오픈빌더의 폴백 블록에 스킬 URL `https://upstage.makertion.com/kakao/skill`을 연결하면 카카오톡 채널에서 같은 방식으로 답합니다. 5초 제한 처리(콜백·"결과 확인"), 응답 모양, 설정은 [카카오톡 연동 안내](docs/kakao-skill.md)를 봅니다.

## 신뢰 장치

1. **인용은 코드가 만든다.** 모델은 제공된 원문 행의 근거 번호만 고르고, `citation` 문자열은 코드가 그 행의 조·항·별표 라벨로 만듭니다. 제공하지 않은 조문이나 자치구 조례가 인용에 들어갈 수 없습니다.
2. **링크·시행일도 코드가 채운다.** `source_url`은 시행 판본이 고정된 법제처 링크, `effective_date`는 그 판본의 시행일입니다.
3. **근거를 확인하지 못하면 답하지 않는다.** 답 자동 검증(모델이 고른 근거가 실제로 찾은 조문인지, 답의 숫자·금액이 원문과 같은지)을 통과하지 못하거나, 조문 확인이 "질문이 묻는 사항을 다루는 규정이 없다"고 답하면 `"확인 불가"`와 빈 인용을 냅니다.
4. **다른 규정으로 넘기는 조문은 조례 내용까지만 답한다.** 조례가 시행규칙·법령에 세부를 맡긴 경우, 조례에서 확인되는 범위와 넘기는 조문을 함께 인용하고 외부 기준을 추측하지 않습니다.
5. **상태를 구분한다.** 시간 초과·처리 오류는 응답 본문은 키트 형식의 "확인 불가"로 두되, 헤더 `X-Rag-Status`와 서버의 작업 기록에 따로 남겨 법적 판단의 "확인 불가"와 섞지 않습니다.
6. **90초 제한 대비.** 80초까지 기다려도 답이 없으면 "확인 불가"를 먼저 돌려주고 작업은 계속하며, 끝난 결과는 `GET /jobs/<작업 번호>`로 받을 수 있습니다.
